# НРІ Асистент — План 12: спільний час для групи

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Майстер кампейну швидко знаходить час, що підходить групі: система пропонує варіанти з календарів, проводить голосування в одне натискання (сайт + Telegram), підказує перенесення, нагадує заповнити календар і вміє імпортувати зайнятість з iCal-посилання. Система лише пропонує — рішення завжди за майстром.

**Architecture:** Новий модуль `backend/src/scheduling/` (підбір часу, голосування, імпорт календаря) поверх наявних календаря доступності (`availability_slots`, `availability_busy_dates`, зайнятість з ігор `calendar/game-busy.service.ts`, `shared/src/schedule/*`), сесій (RSVP, reschedule, `PUT /api/games/:id/schedule`), сповіщень і Telegram-бота (inline-кнопки `bot/src/delivery/callbacks.ts`). Фронтенд — спільні сторінки/діалоги (не слоти дизайнів).

**Tech Stack:** як у попередніх планах; для iCal — бібліотека розбору ICS з підтримкою RRULE (напр. `node-ical` або `ical.js`; безкоштовно, без зовнішніх сервісів).

**Spec:** погоджено з власником 2026-11-26 (пам'ять `group-scheduling-feature`): пункти 1, 2, 3, 5 + імпорт; автоматичних рішень (кворум) немає.

## Global Constraints

- Лише пропозиції: жодна дія не змінює розклад без підтвердження майстра.
- Підбір часу (`GET /api/games/:id/common-times`, лише майстер гри): для кампейну й активних учасників (+ майстер) на горизонті 4 тижні, сітка 30 хв, тривалість = `durationMinutes` гри; для кожного кандидата — хто може / не може / невідомо (порожній календар); враховує тижневі слоти (з переведенням поясів учасників у пояс гри), зайняті дати, зайнятість з інших ігор і імпортовані iCal-інтервали; топ-5 «регулярних» (день тижня + час) і топ-5 «разових» (конкретна дата) за кількістю «можуть», далі за ранішим часом.
- Голосування: майстер створює 2–6 варіантів (заповнені з підбору або вручну), дедлайн (≤ 14 днів); учасник відповідає «можу / не можу / якщо треба» (змінювати до закриття); закривається, коли проголосували всі активні учасники або настав дедлайн; результат — підсвічений переможець; застосувати (новий розклад кампейну або перенесення конкретної сесії) може лише майстер, через наявні API. Telegram: inline-кнопки в сповіщенні про голосування (наявний механізм callback).
- Розумне перенесення: коли учасник ставить «не буду» на сесію, майстер отримує сповіщення з посиланням; на сесії майстер бачить 3 найближчі альтернативи (той самий підбір на тиждень сесії) і переносить одним кліком через наявний reschedule.
- Нагадування про порожній календар: учаснику кампейну без тижневих слотів — одне сповіщення (через 24 год після вступу або при першому запуску джоба для наявних учасників), ніколи не повторюється (зберігати час).
- Імпорт iCal: користувач вставляє https-посилання (Google «секретна адреса у форматі iCal», Apple, Outlook); сервер періодично (кожні 3 год) завантажує з таймаутом 10 с, лімітом розміру 2 МБ, лише https, з захистом від SSRF (заборонені приватні/loopback/link-local адреси після DNS-резолву, без редиректів на них); зберігаються лише інтервали зайнятості на горизонті 8 тижнів (без назв і описів подій); посилання зберігається зашифровано або щонайменше не віддається назад у API (показується як «підключено …»); помилки завантаження видно користувачу; відключення видаляє дані.
- Час — у поясі глядача без позначки поясу. Тексти — `uk.json` і шаблони бота. Права — на бекенді. Міграції — drizzle-kit. Тести/typecheck/lint/build зелені; один процес тестів бекенду; ролі в dev-БД не змінювати; медіа лише в `.media/`.

## Review Focus

1. Переведення поясів і DST у підборі часу (учасник у Варшаві, гра в Києві, перехід на літній час у горизонті).
2. Права: підбір, створення/застосування голосування — лише майстер; голосують лише активні учасники; Telegram-callback перевіряє, що користувач — учасник.
3. SSRF і зловмисні ICS (величезний файл, нескінченна RRULE, редирект на 127.0.0.1, повільна відповідь).
4. Ідемпотентність джобів (закриття голосувань, нагадування, імпорт) при перезапусках.
5. Порожні/часткові календарі не ламають підбір («невідомо» не дорівнює «може»).
