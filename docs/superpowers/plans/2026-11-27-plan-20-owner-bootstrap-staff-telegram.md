# План 20 — власник через Telegram з `.env` і обов'язковий Telegram для персоналу

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** на новому сервері (бета чи реліз) власник платформи стає власником автоматично — акаунт, створений через вхід Telegram з id з `.env`. Увесь персонал (модератори, адміни, власник) обов'язково має прив'язаний Telegram.

**Spec:** рішення власника в чаті 2026-11-27.

## Global Constraints

- **`OWNER_TELEGRAM_ID`** у `.env` бекенду (числовий Telegram user id; необов'язковий у local, рекомендований на dev/prod — у шаблонах і `docs/ops/deploy.md` серед кроків власника).
  - Коли користувач входить через Telegram (або прив'язує Telegram), і його Telegram id = `OWNER_TELEGRAM_ID`, а **власника на платформі ще немає** — він стає власником (`role = owner`), подія в журналі.
  - Якщо власник уже є і це інша людина — нічого не змінюється (передача власності — наявною функцією), у лог — попередження раз на старт/вхід.
  - Якщо id не задано — поведінка як зараз.
- **Персонал лише з Telegram:**
  - Призначити користувача модератором/адміном (і передати власність) можна лише якщо в нього прив'язаний Telegram; інакше 409 `TELEGRAM_REQUIRED` з поясненням в адмінці («Спершу користувач має прив'язати Telegram»).
  - Персонал не може відв'язати Telegram (409 з поясненням), доки має роль; спершу зняти роль.
  - Наявний персонал без Telegram (dev-дані, локальні акаунти): роль не знімається автоматично; в адмінці «Ролі» біля такого — позначка «Без Telegram», і він отримує сповіщення на сайті з проханням прив'язати (одне, без повторів). Власник локального dev-середовища («Дошка_Власник») лишається власником.
  - Dev-вхід (План 19) у local не обмежується цим правилом для входу, але призначення ролей — так.
- Тексти — `uk.json`; тести/typecheck/lint зелені; секрети не друкувати й не комітити; не змінювати ролі користувачів наявної dev-БД вручну.

## Review Focus

- Бутстрап власника спрацьовує рівно один раз і лише для точного Telegram id; гонка двох входів не створює двох власників.
- Підробка: id береться лише з перевіреного підпису Telegram-входу (наявна перевірка), не з тіла запиту/бота без підпису.
- Інваріант «персонал ⇒ Telegram» тримається на всіх шляхах: призначення ролі, передача власності, відв'язка Telegram, видалення акаунта.
